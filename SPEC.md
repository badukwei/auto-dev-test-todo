# Todo API Specification

## Objective

Build a minimal REST API for managing Todo items. The API must persist data in
SQLite and be fully covered by automated endpoint tests.

## Data model

A Todo has these fields:

| Field | Type | Rules |
| --- | --- | --- |
| `id` | integer | Generated by the server; unique |
| `title` | string | Required; must not be empty or whitespace-only |
| `completed` | boolean | Defaults to `false` |

Responses must not expose internal SQLAlchemy state.

## API behavior

### Create a Todo

`POST /todos`

Request body:

```json
{
  "title": "Write tests"
}
```

Requirements:

- Return `201 Created`.
- Return the created Todo, including its generated `id`.
- Set `completed` to `false`.
- Reject a missing, empty, or whitespace-only title with `422 Unprocessable
  Entity`.

### List Todos

`GET /todos`

Requirements:

- Return `200 OK`.
- Return a JSON array.
- Return an empty array when no Todos exist.
- Return Todos in ascending `id` order.

### Complete a Todo

`PATCH /todos/{id}/complete`

Requirements:

- Return `200 OK`.
- Set `completed` to `true`.
- Return the updated Todo.
- Calling the endpoint again for an already completed Todo must remain
  successful and return the same completed state.
- Return `404 Not Found` when the Todo does not exist.

### Delete a Todo

`DELETE /todos/{id}`

Requirements:

- Return `204 No Content` with an empty response body.
- Remove the Todo from subsequent list results.
- Return `404 Not Found` when the Todo does not exist.

## Persistence

- Use SQLAlchemy for database access.
- Use SQLite as the database.
- Data must persist across application restarts when running normally.
- Tests must use an isolated temporary or in-memory database and must not alter
  the development database.

## Automated tests

At minimum, tests must cover:

- creating a valid Todo;
- rejecting missing, empty, and whitespace-only titles;
- listing zero and multiple Todos;
- completing an existing Todo;
- completing an already completed Todo;
- completing a nonexistent Todo;
- deleting an existing Todo;
- deleting a nonexistent Todo; and
- confirming deletion affects subsequent list results.

## Documentation

Update `README.md` with:

- prerequisites;
- installation instructions;
- the command to start the API;
- the commands to run tests and lint checks; and
- brief example requests or a link to FastAPI's generated API documentation.

## Out of scope

Do not implement:

- authentication or users;
- due dates, priorities, tags, or filtering;
- a frontend;
- Docker or deployment configuration;
- pagination;
- cloud databases or external services.

## Acceptance criteria

The task is complete only when:

1. All four endpoints behave as specified.
2. Data persistence and test isolation requirements are met.
3. `pytest` passes without test failures.
4. `ruff check .` passes.
5. The application starts using the command documented in `README.md`.
6. The repository contains no unrelated features or infrastructure.
